RpmArea V10 - KEAMANAN DATA / PEMULIHAN
====================================
PERINGATAN PENTING: Data yang sudah tertimpa pada V8/V9 tidak otomatis kembali setelah memasang V10.

Gejala lama: unggah awal 865 dokumen berhenti 0%, lalu sesudah refresh tampilan kosong.
Akar risiko di V8/V9: pada masuk ulang cloud yang memuat sebagian dokumen, callback onSnapshot langsung
memanggil AreaApp.applyRemote() dan mengganti SELURUH data lokal dengan snapshot cloud tanpa backup.

PERTOLONGAN SEBELUM UPDATE
1. Jangan clear site data/cache, uninstall aplikasi, atau upload data yang tidak lengkap.
2. Cari Backup_SalesPulse_Area_*.json dari folder Download atau perangkat lain.
3. Jika layar memiliki data, unduh Backup JSON dari menu Master Toko / Pengaturan.
4. Cek Riwayat Bulanan dan pilihan bulan/minggu agar tidak terkecoh filter.
5. Jika ada perangkat lain berisi data lama, matikan koneksi data perangkat tersebut, buka,
   lakukan backup JSON terlebih dahulu sebelum cloud sempat menyinkronkan.

PERBAIKAN V10
- Mencegah cloud parsial mengganti data lokal pada koneksi pertama.
- Jika data lokal berbeda dari cloud, pemrosesan ditahan sampai pengguna membandingkan backup.
- Jika cloud persis subset data lokal, tersedia tombol unggah HANYA dokumen yang belum ada.
- Tidak otomatis menghapus data dari Firestore pada proses pemulihan.
- Sebelum menerapkan snapshot cloud, data lokal disimpan dahulu ke IndexedDB (Safety Vault).
- Pusat Pemulihan Data di ./recovery.html: unduh data lokal, snapshot otomatis, atau cloud (read only).
- Galat Firestore permission-denied menghentikan retry otomatis agar tidak tampak menggantung.

CATATAN
- V10 tidak dapat mengembalikan versi lama jika V8/V9 telah menimpa data dan tidak ada backup.
- Periksa jumlah minggu, toko, PLU di file sebelum memilih Restore JSON.
- Firestore Rules/keanggotaan harus membolehkan write ke workspaces/rpm-area-12/records/{doc}.
- Pengujian live Firebase perlu dilakukan di proyek pengguna; tidak ada akses ke data cloud akun.
