RPM AREA V25 — TARGET GAP 100% POINT DAN KUOTA SUPABASE

FITUR GAP QTY / NS / POINT
1. Buka Home > Kekurangan menuju POINT 100%.
2. Pilih tanggal sebelumnya/berikutnya pada Time Factor: pencapaian dan kebutuhan tambahan menyesuaikan.
3. Untuk toko, lihat: kekurangan QTY ke 100%, kekurangan NS ke 100%, dan simulasi unit tambahan untuk mencapai POINT 100%.
4. Pilih PLU spesifik di kartu toko untuk menghitung tambahan QTY berdasarkan HPP/NS per unit produk itu.
5. Jika memilih rata-rata aktual, aplikasi menggunakan total NS hingga tanggal pilihan dibagi total QTY; saat belum ada transaksi pilih PLU manual.
6. Formula POINT=50*(QTY aktual/target QTY + NS aktual/target NS). Kebutuhan tambahan x = ceil( (2-QTY/TQ-NS/TN)/(1/TQ+HPP/TN) ), minimum nol.
7. Kekurangan QTY 100% dan NS 100% adalah indikator terpisah. POINT bisa 100% walaupun salah satunya belum 100%. Ini bukan prediksi penjualan nyata.

KUOTA SUPABASE (LANGKAH WAJIB SEKALI)
1. Di proyek RPM-AREA-12, buka Supabase > SQL Editor > New Query.
2. Salin isi supabase-quota-rpc.sql dari ZIP ini, lalu tekan RUN. Tidak mengubah data penjualan dan aman diulang.
3. Deploy seluruh file V25, login lewat Cloud > Sinkronisasi Cloud.
4. Tekan Perbarui DB untuk melihat estimasi ukuran database terpakai/sisa terhadap 500 MB.
5. Untuk Egress: buka link Usage resmi Supabase, lihat egress TERPAKAI pada periode berjalan (lingkup organisasi), lalu masukkan nilai MB di kolom manual.
6. Jangan masukkan Supabase personal access token, service_role, maupun secret key ke aplikasi web. Nilai yang tidak tersedia akan ditampilkan —, tidak dikarang.
7. Ukuran DB melalui pg_database_size adalah estimasi teknis. Angka dan kuota resmi tetap di Supabase Dashboard. Paket Free dapat berubah.
